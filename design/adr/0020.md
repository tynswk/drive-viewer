# ADR-0020 開いたものは端末に保存し、先に出してから裏で版を確かめる

- 日付：2026-11-15
- 状態：採用

**決めたこと**：
- ファイルの本文（md・テキスト・HTML・PDF）、フォルダの中身、「最近」の一覧を、端末の IndexedDB（`dv-cache`）に保存する（docs/app/cache.js）。
- 開くときは保存した本文を先に出し、裏で版（version）を確かめる。同じなら通信はその1回で終わり、違えば本文を取り直して差し替える。編集中なら差し替えず、トーストで知らせる（保存時に衝突として扱われる）。
- 保存が無いときは、版の確認と本文の取得を同時に走らせる。取れた本文のバイト数が版の確認で得た size と違えば、その間に書き換えられたとみなし、版→本文の順で取り直す。
- 取得は、指が行に触れた時点（pointerdown）で始める。フォルダの中身も同じ。
- 本文の上限は1ファイル30MB・合計150MB。超えたら古く保存したものから捨てる。ログアウトで全部消す。
- 起動時は、保存した前回の「最近」の一覧を先に出し、取り直した結果で差し替える。

**理由**：PCのChromeで測ると、mdを開くのに1.8秒かかっていた（版の確認0.39秒→本文1.37秒の直列）。フォルダを開くのは0.5秒で、中身は再起動すると忘れていた。エージェントと作業しているときは同じファイルを何度も開き直すので、2回目以降を速くするのが一番効く。変更後の実測（PC・指が触れてから表示まで）は次のとおり。
- 再訪の md：約0.13秒（ほぼ待ち時間なし）
- 初めての md：1.2秒
- 起動から一覧が出るまで：0.27秒（以前は2.6秒）

**捨てた案**：
- Service Worker の Cache API に Drive の応答を置く：版と本文を組で持てず、版の照合が書きにくい。
- 版を確かめずに保存を出すだけにする：エージェントが書き換えた後も古い本文を見続けてしまう。
- 同時取得の食い違いを無視する：版だけ新しく本文が古いと、保存で相手の変更を上書きしてしまう。
